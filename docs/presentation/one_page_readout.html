Red team 12 defects found and fixed after the build was “done” · 8 new regression tests

Every one of these passed 138 green tests. They survived because the fixtures were hand-written with clean values and egress is blocked, so no real payload ever crossed the boundary. Two would have taken the desk down on day one. This is the argument for a red-team pass as a build step rather than a phase: a green suite proves the code does what the tests say, not what the source does.

iddefectwhat it would have cost in production
RT-01Every real price failed validation. decimal_places=6 is a maximum in pydantic; Yahoo serializes doubles, so 226.03999328613281 raised.Total outage of the price path, presenting as “source unavailable.” Days lost blaming the vendor.
RT-02The NYSE calendar was bounded only above. Any date before 2026 scored against the 2026 holiday table: 2025-12-25 and 2024-07-04 both returned regular session.A backfill or fixture replay marked tradeable on Christmas. Silent, and wrong in the direction that fetches.
RT-11The poller exited 0 on failure. main() compared status to the literal "FAILED", so FAILED_NO_DATA, both INDETERMINATE states and FALLBACK_REQUIRED all reported success.Cron logs green over a desk serving nothing. The failure mode CLAUDE.md #6 exists to prevent, in the monitoring layer.
RT-03/04Only HTTPError was caught. A reset or timeout on the EDGAR leg propagated out, killed the price leg, and skipped save_state() — losing the ETag and the call counters with it.One network blip burns the conditional-GET cache and double-charges the monthly cap.
RT-07A cache hit returned no row. The dedupe that justifies the entire call budget delivered {"status":"cache"} and nothing else.The budget design was decorative: N advisors, N calls.
RT-05/06The audit record lied. The exception was discarded, so a parser bug and a vendor outage wrote identical failure rows; the recovery path wrote “verified by a second read” when nothing was verified.Un-triageable incidents, and an audit trail that misstates what happened — the worst kind, because it is confident.
RT-12A clean checkout could not run. make setup installed jsonschema (imported nowhere) and not pydantic (imported everywhere).Every new engineer's first hour. Now pinned in requirements.txt.
RT-13Thirteen S&P 500 tickers are English words. The front-end resolver read “Why is it down today?” as Gartner (IT) and “what is that worth right now?” as ServiceNow (NOW).The precise failure this system exists to prevent: a confident, sourced, fully-cited answer about the wrong company. Found by running the page headless, not by reading it.

Excluded from this list as boundary conditions, not defects: blocked egress, the stub eval adapter, the absent entitled feed, and the absent agent runtime. Those are known and scoped. Also fixed but not tabled: RT-09 (the documented cron and make poll both used a 15-minute interval that the budget refuses to start on) and RT-10 (retrieved_at stamped at the top of the cycle, so a slow EDGAR call made a fresh print fail as “a quote from the future”).

Burndown to production ranked, dependencies first

  1. Agent runtime — implement SystemAdapter.invoke and the six domain agents. Until this lands, nothing is measured.
  2. Entitled market-data feed — delete the interim source path; bid/ask/spread and halt status arrive with it.
  3. Orion + clearing reads — intraday quantity, so a notional stops mixing T-1 shares with a live price.
  4. Retention and audit pipeline — raw turn persisted before compaction, immutable, exportable.
  5. WSP rule table + supervision agent — the flag endpoints have no referent until the rules have ids.
  6. AuthN/AuthZ wiring — the RLS boundary is only real if the runtime connects as the agent's role.
  7. Eval corpus + first real baseline, then drift on every deploy.
  8. Observability — failure_log and hitl_queue triage in front of a human, not in a table.
  9. Scale to a watchlist and re-measure cost: the cap scales linearly with symbol count.
  10. HA, backup, key management, DR.
  11. Front-end test suite — headless per-intent assertions, so a resolver change cannot silently answer about the wrong issuer again.
