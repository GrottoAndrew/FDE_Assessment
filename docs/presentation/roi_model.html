Routing

Three tiers, assigned by what the task requires

The tiers are ordered by the kind of thinking the job needs, not by how important it feels. An agent moves up a tier only when a cheaper model demonstrably fails its golden cases — never on intuition.

The counter‑intuitive result

Routing the leaf agents down to Haiku and Sonnet saves 13 points. Caching the stable prefix — system prompt, tool schemas, policy YAML — saves 34.5. Caching wins because it applies to every call including the expensive ones, while routing only helps on calls that were already cheap.

Two Opus agents run on every single task: the orchestrator and the red teamer. They dominate the bill. That is why the biggest remaining lever is a single routing decision, not twelve.

The lever not pulled, and why

Moving the orchestrator to Sonnet would take total cost to $123/month — a further 21 points. It is not in the build because the orchestrator is the component that decides what happens next, and no eval has been run showing Sonnet holds routing quality on this workload.

That is a measurable question, not a matter of taste: run the golden set with the orchestrator on each model and compare per-case results. Until that exists, taking the saving would be trading a known cost for an unknown error rate.

Defending the number

How to present this

  1. Lead with unit cost, not percentage. “$0.042 per completed task” survives scrutiny; “70% cheaper” immediately invites “than what?”
  2. Decompose before you are asked. Caching 34.5, routing 13.1, and name the 21 you left on the table.
  3. State the assumption out loud. 70% cache hit rate and the token profiles are estimates until measured from eval_output/. Say so.
  4. Give the break‑even in human minutes. At $0.042 per task, the model cost is noise against a loaded labour minute — so the real argument is throughput and consistency, not token savings. Make that argument instead.
